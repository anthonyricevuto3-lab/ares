# Risk register

NPR 7150.2D SWE-086 says the project manager shall record, analyze, plan, track, control, and communicate software risks and mitigation plans. The note says remaining risk after mitigation or acceptance should stay visible. Likelihood and impact here are qualitative. No probabilities are assigned.

| ID | Description | Likelihood | Impact | Mitigation | Residual risk | Status |
| --- | --- | --- | --- | --- | --- | --- |
| ARES-RSK-001 | Host SteadyClock scheduling makes a short chaos window easy to miss, so a demo can finish Nominal without the restart the scenario intended. | Occasional on a loaded workstation | A demonstration can be misread if only the process exit is checked | Demo wrappers require the summary lines. ManualClock campaigns are the repeatable evidence. | A busy host can still fail the navigation demo wrapper. | Open, accepted for demos |
| ARES-RSK-002 | MSVC cannot compile the `__int128` integration path. | Certain if MSVC is selected | Configure fails | CMake stops with a fatal error that names UCRT64 GCC or Clang. | No MSVC build exists. | Open, accepted |
| ARES-RSK-003 | ThreadSanitizer cannot start under the current WSL memory mapping. | Certain in that environment | Data-race evidence is missing | Functional join and mailbox tests. Do not claim a TSan pass. | Races could exist that the functional tests do not catch. | Open |
| ARES-RSK-004 | The Windows ZIP needs the UCRT64 runtime DLLs on `PATH`. | Certain on a machine without MSYS2 | The executable does not start | Release notes and the README name `libstdc++-6.dll`, `libgcc_s_seh-1.dll`, and `libwinpthread-1.dll`. | The ZIP is not standalone. | Open, accepted |
| ARES-RSK-005 | The 32-entry miss history overflows on a long delay and the process exits 9 after recovery has already failed. | Expected when the delay outlasts the history | Diagnostic overflow after a valid RecoveryFailed | Wrappers accept exit 0 or 9 only when `recovery_failures: 1` is exact. The overflow is not hidden. | Operators who ignore the summary can confuse exit 9 with a recovery failure. | Open, accepted |
| ARES-RSK-006 | Simulated sensors assume a single reader. A second reader would consume or alias a sample. | Low in the current task set | Split or repeated samples | Coding standard documents the assumption. GPS tests check one read per selection. | A new task that reads the same sensor is not mechanically rejected. | Open |
| ARES-RSK-007 | SteadyClock demo timing varies from run to run. Recordings are not byte-identical on the host clock. | Certain | Two host recordings of one scenario differ | Document the split between ManualClock and SteadyClock. Campaign tests use ManualClock. | Host recordings are not a bitwise oracle. | Open, accepted |
| ARES-RSK-008 | Toolchain and platform differences (GCC 16 on UCRT64 versus Clang on Linux CI) can diverge. | Low while CI is green | A defect visible on only one compiler | Both compilers are in the verification set. Warnings are errors. | A platform not in CI is untested. | Open, watched |
| ARES-RSK-009 | Offline replay does not re-execute flight software, so a recording can look valid while a behavior change would have diverged. | Certain by design | Replay is not a second flight run | Replay checks structure, CRC, and sequence. Campaigns re-execute flight code. | Replay cannot catch a logic change that was never recorded. | Open, accepted |
